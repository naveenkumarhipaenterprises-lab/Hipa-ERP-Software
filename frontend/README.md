# HIPA MASALA — Frontend

React + Vite frontend for the HIPA MASALA Business Analytics Software.

**The frontend contains no sample, mock or hard-coded business data.** Every number, table row, chart, insight and AI answer comes from the Django REST API. When the API has no data or cannot be reached, screens show empty, loading or error states instead. Forecasts, purchase recommendations and AI insights are produced by the backend / AI engine. The frontend only displays them.

## Run

```bash
npm install
cp .env.example .env     # Windows: copy .env.example .env
npm run dev              # http://localhost:5173
```

| Variable | Purpose |
|---|---|
| `VITE_API_BASE_URL` | Where the browser sends API calls. Keep `/api/v1` in development (the backend's versioned API). |
| `API_PROXY_TARGET` | Development only: the Django server that `/api` is forwarded to (default `http://localhost:8000`). Not included in the build. |
In production the web server must return `index.html` for every path that doesn't start with `/api`, so addresses like `/sales` work on refresh.

## Backend contract

The API files document each endpoint, including the exact request and response shapes the backend must provide:

| Area | File |
|---|---|
| Login, logout, password reset | `src/api/authApi.js` |
| Notifications | `src/api/notificationsApi.js` |
| Dashboard | `src/api/dashboardApi.js` |
| Sales, Inventory, Customers, Purchase | `src/api/salesApi.js`, `inventoryApi.js`, `customersApi.js`, `purchaseApi.js` |
| Marketing, Supply Chain, Quality, Finance | `src/api/marketingApi.js`, `supplyChainApi.js`, `qualityApi.js`, `financeApi.js` |
| Reports, AI Assistant, Settings | `src/api/reportsApi.js`, `aiApi.js`, `settingsApi.js` |

General rules:
- Paths in the API files are relative to `VITE_API_BASE_URL`, e.g. login is `POST /api/v1/auth/login/`. The backend lives in `../backend` (see its README).
- Login (`POST /auth/login/`) returns `{ access, user: { id, name, email, role } }`. The token is sent as `Authorization: Bearer <access>`. A 401 on a signed-in request ends the session and shows "Your session has ended".
- Lists are paginated in DRF style: `?page=&page_size=` returning `{ count, results }`.
- Validation errors use DRF's format (`{ field: ["message"] }`) and appear under the matching form field. `{ detail }` appears as a banner.
- Choice lists (customers, products, categories, statuses, platforms and so on) come from each module's `options/` endpoint. The frontend has no built-in business lists.
- Files (exports, reports, backups) are generated by the server and downloaded as-is.
- The backend must enforce every role rule below. The frontend hides what a role can't use, but that is not security.

## Roles

Menu access is configured in `NAV_ITEMS` in `src/utils/constants.js`:

| Module | Roles that can open it | Roles that can change data |
|---|---|---|
| Dashboard, AI Assistant, Reports | all | — |
| Sales | admin, management, sales, marketing, finance | admin, management, sales |
| Inventory | admin, management, inventory, purchase, supply_chain | admin, management, inventory |
| Purchase | admin, management, purchase, inventory, finance, supply_chain | admin, management, purchase · supplier payments: also finance · raw-material usage: also inventory |
| Marketing | admin, management, marketing | admin, management, marketing |
| Customers | admin, management, sales, marketing | edit: admin, management, sales · offers: admin, management, marketing |
| Supply Chain | admin, management, inventory, quality, purchase, supply_chain | admin, management, inventory, supply_chain |
| Quality | admin, management, quality, purchase | admin, management, quality |
| Finance | admin, management, finance | admin, management, finance |
| Settings | admin, management | admin, management |

## Structure

```
src/
  api/          client.js (axios, errors, downloads, uploads) + one file per module
  components/
    auth/       login form, password field, language and sign-on buttons
    charts/     SeriesChart, DonutChart, ProgressList, Sparkline (all with empty states)
    common/     Button, Card, Table, Modal, FormModal, ConfirmDialog, OptionsGate, inputs…
    dashboard/  StatCard, QuickActions, insight panels
    navigation/ Sidebar, Topbar, notifications and user menus
  context/      AuthContext, ToastContext
  hooks/        useApi, useAuth, useToast, useDebouncedValue, usePageReset,
                useFocusTrap, useDismiss, useMediaQuery
  layouts/      AuthLayout (login pages), MainLayout (app shell)
  modules/      one folder per business module: page + components
  pages/        Login, ForgotPassword, ResetPassword, Dashboard, NotFound
  routes/       AppRoutes, ProtectedRoute, PublicRoute
  services/     authService
  test/         shared test setup
  utils/        constants (menu + roles), formatters (₹, dates), validation, exporters
e2e/            end-to-end tests (Playwright)
```

## Scripts

- `npm run dev`: development server
- `npm run build`: production build to `dist/`
- `npm run lint`: ESLint
- `npm test`: unit and component tests (Vitest)
- `npm run test:watch`: the same, re-running on every file change
- `npm run test:e2e`: end-to-end tests in Microsoft Edge (Playwright)
- `npm run test:all`: lint, unit tests and end-to-end tests together

## Tests

No backend is needed for any test. Fake API replies exist only inside the test files (marked `TEST`) and are never part of the app.

- **Unit and component tests** sit next to the code as `*.test.js(x)` files under `src/`. They cover formatting (₹, dates), form validation, the API client's error handling, safe login redirects, CSV export and the shared components. They run in a simulated browser (jsdom) in a few seconds.
- **End-to-end tests** live in `e2e/`. They start the dev server on port 5181 and use the Microsoft Edge already installed on Windows, so no browser download is needed. They cover login and session expiry, role-based menus, the empty, error and filled data states, creating and cancelling an order, and that no page scrolls sideways at laptop, tablet and phone widths. Any API call a test doesn't define gets a "server unavailable" reply.
- After a failed end-to-end run, open `playwright-report/index.html` for screenshots and step-by-step traces.

## Browser support

Tested in Microsoft Edge (Chromium), so current Chrome behaves the same. Firefox and Safari have not been tested yet. Layouts are checked at 1920, 1366, 1024, 768 and 375 px wide.
